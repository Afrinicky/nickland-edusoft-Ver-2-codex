# Where each part of the office application works

**Nickland Edusoft · Copyright © 2026 Nickland Sales**

> Generated by `node scripts/desk-coverage.mjs`. Do not edit it by hand —
> it is regenerated from the application's own channel list and from the
> hosted service's map, so it cannot drift away from either.

The office application is one application with three ways in. This says
which of them answers what, because "it works on the office computer but
not on the website" is a thing a school should be able to look up rather
than discover.

| | What it is | Answers |
|---|---|---|
| **The installed application** | The school's own computer | all 408 |
| **A browser on the school network** | Any machine on the school Wi-Fi, and the installed application in client mode | 381 of 408 (93%) |
| **Hosted — the installer's own code** | The internet, running host/server.js | 381 of 408 (93%) |
| **Hosted — the Python service** | The internet, running cloud-python | 107 of 408 (26%) |

There are two ways to be hosted and they are not equal. **host/server.js**
runs the installed application's own handlers on a server — the same code, so
it answers everything a browser on the school network does, and it cannot
drift, because there is nothing for it to drift from. The Python service is a
separate implementation and answers what has been carried over to it. The
per-channel table below is about that one.

Three things a channel can be:

* **✓ online** — the hosted service answers it.
* **office PC** — it only means something on the school's own machine: opening a
  folder, restoring a backup, a file dialog. Not missing; located.
* **not yet** — the hosted port has not reached it. The screen says so in
  words and points at the school's computer, rather than failing.

Everything not marked **office PC** works over the school network today.
